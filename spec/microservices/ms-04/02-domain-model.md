# Cart and Checkout — Domain Model

**Service ID:** MS-04  
**Database:** PostgreSQL  
**Schema:** `cart_checkout_schema`  
**Ownership:** Cart and checkout data only.

MS-04 does not create foreign keys into MS-01, MS-02, MS-05, MS-06, MS-07, MS-08, MS-09, MS-10, MS-11, or MS-12 schemas. Customer, product, order, payment, price, tax, shipping, store, and configuration identifiers are opaque references resolved through service contracts.

## Entity lifecycle

### Cart lifecycle

- **States:** `OPEN` (initial), `COMPLETED` (terminal), `OBSOLETE` (terminal)
- **Transitions:**

| From | To | Trigger | Guard |
|---|---|---|---|
| — | `OPEN` | BR-SC-CRE-001 | Cart is created with tenant and store scope |
| `OPEN` | `COMPLETED` | BR-CO-ORC-019 | Local submission transaction commits and `OrderSubmitted` is durably queued |
| `OPEN` | `OBSOLETE` | BR-SC-HYD-006 | No line remains usable after hydration |
| `COMPLETED` | — | — | Terminal; cart cannot be reused |
| `OBSOLETE` | — | — | Terminal; cart cannot be reused |

### Checkout session lifecycle

- **States:** `OPEN` (initial), `QUOTED`, `FROZEN`, `SUBMITTED` (terminal), `FAILED` (terminal), `EXPIRED` (terminal)

| From | To | Trigger | Guard |
|---|---|---|---|
| — | `OPEN` | BR-CO-STA-018 | Session created for an open cart |
| `OPEN` | `QUOTED` | BR-SC-TOT-010 | Current totals and provider quote references stored |
| `QUOTED` | `FROZEN` | BR-CO-SNP-014 | Cart version, quote versions, and total hash still match |
| `FROZEN` | `SUBMITTED` | BR-CO-ORC-019 | Idempotency record and outbox event committed |
| `FROZEN` | `FAILED` | BR-CO-TOT-015 / BR-CO-PAY-016 | Permanent validation or payment-handoff failure |
| `OPEN` | `EXPIRED` | BR-CO-STA-018 | Session expiration reached |
| `QUOTED` | `EXPIRED` | BR-CO-STA-018 | Session expiration reached |
| `FROZEN` | `EXPIRED` | BR-CO-STA-018 | Session expiration reached before submission |
| `SUBMITTED` | — | — | Terminal |
| `FAILED` | — | — | Terminal |
| `EXPIRED` | — | — | Terminal |

## Data invariants

| Invariant ID | Statement | Entity | Kind | Tier |
|---|---|---|---|---|
| INV-SC-001 | A cart code is unique within tenant and store scope | `shopping_cart` | constraint | both |
| INV-SC-002 | A cart line quantity is positive while the line exists | `shopping_cart_item` | constraint | both |
| INV-SC-003 | A cart line subtotal equals unit price multiplied by quantity | `shopping_cart_item` | computed | both |
| INV-SC-004 | Cart and checkout records cannot reference multiple tenant/store scopes | cart and checkout tables | cross-entity | both |
| INV-CO-001 | A frozen checkout cannot be modified | `checkout_session` | lifecycle constraint | app |
| INV-CO-002 | A submitted checkout has exactly one immutable submission result | `checkout_submission` | constraint | both |
| INV-CO-003 | A replayed idempotency key returns the original response | `checkout_idempotency_key` | constraint | both |
| INV-CO-004 | Grand total equals subtotal minus discounts plus shipping, handling, and tax | `checkout_total_snapshot` | computed | both |
| INV-CO-005 | Terminal checkout states have no outgoing transition | `checkout_session` | lifecycle constraint | app |
| INV-CO-006 | An outbox event is published only after the local transaction commits | `ms04_outbox` | cross-entity | both |

## Placement candidates

| Candidate | Legacy tier | Data-volume signal | Set-vs-row | Call frequency | App-tier risk | Default |
|---|---|---|---|---|---|---|
| Cart hydration and line repricing | Application service | One cart and all its lines per cart read; broad checkout graphs reach hundreds of catalog nodes | Row-at-a-time line loop | Every cart read, total, and checkout | Repeated provider calls can increase latency; batching is required | App/domain |
| Total orchestration | Application service | All cart lines plus provider allocations, tax lines, shipping, and handling | Row-at-a-time aggregation over bounded cart | Interactive totals and checkout | Reimplementing provider formulas causes divergence | App/domain |
| Checkout snapshot | No legacy equivalent | One immutable snapshot per submitted checkout | Set-like local transaction over cart lines | Checkout only | Partial persistence can cause duplicate order/payment effects | App + database |
| Idempotency | No legacy equivalent | One key per submission attempt | Unique index lookup | Every payment-sensitive mutation | Retry storms can repeat provider calls | App middleware + database |
| Outbox publication | No legacy equivalent | One event per accepted submission | One-row durable write | Every accepted checkout | Direct event publishing before commit loses or duplicates submissions | App + database |
| Broad order joins | Legacy MS-05 path | Large fetch graphs across order products, totals, history, downloads, and prices | Set/read-model candidate | Administrative reads | Row multiplication and memory pressure | MS-05 read model |

## Ownership boundaries

- `shopping_cart`, `shopping_cart_item`, and `shopping_cart_attr_item` are MS-04-owned legacy concepts.
- `checkout_session`, snapshots, submission, idempotency, quote references, and outbox are MS-04 target concepts.
- `ORDERS`, `ORDER_PRODUCT`, `ORDER_PRODUCT_ATTRIBUTE`, `ORDER_PRODUCT_PRICE`, `ORDER_PRODUCT_DOWNLOAD`, `ORDER_STATUS_HISTORY`, and `ORDER_TOTAL` belong to MS-05.
- `SM_TRANSACTION` belongs to MS-06.
- Product and availability data belong to MS-02.
- Price and promotion allocations belong to MS-07.
- Tax quote data belongs to MS-08.
- Shipping quote and carrier data belong to MS-09/MS-12.
- Customer and address data belong to MS-01.
- Store and configuration data belong to MS-10/MS-11.
