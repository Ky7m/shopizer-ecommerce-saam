# Order Management — Domain Model

**Service:** MS-05  
**Schema:** `order_management`  
**Database:** PostgreSQL 15+  
**Ownership:** Order lifecycle and immutable order snapshot

## Modeling Decisions

- Legacy `SM_TRANSACTION` is not owned by MS-05; payment transaction state belongs to MS-06.
- Cart tables are not owned by MS-05; MS-04 supplies an immutable submitted snapshot.
- `ORDER_ACCOUNT` and `ORDER_ACCOUNT_PRODUCT` are retained as conditional migration candidates only. No active order-management behavior in the reviewed source establishes subscription ownership.
- No invoice table is created because the active invoice implementation is not implemented and no invoice table was present in the CAST order data graph.
- Target-only `fulfillment_order`, `fulfillment_status_history`, `order_inbox`, and `order_outbox` are justified by BR-OR-FUL-001, BR-OR-RES-001, and the brief's required saga/event boundaries.

## Entity State Model

### `orders` lifecycle

- **States:** `ORDERED` (initial), `PROCESSED`, `DELIVERED`, `REFUNDED` (terminal), `CANCELED` (terminal)
- **Transitions:**

| From | To | Trigger | Guard |
|---|---|---|---|
| `ORDERED` | `PROCESSED` | BR-OR-PAY-002 | Authenticated capture outcome or approved administrative transition |
| `ORDERED` | `CANCELED` | BR-OR-CAN-001 | No terminal fulfillment state; payment compensation can be initiated |
| `PROCESSED` | `DELIVERED` | BR-OR-FUL-001 | Fulfillment update is `DELIVERED` |
| `PROCESSED` | `REFUNDED` | BR-OR-REF-001 | Cumulative applied refund equals captured amount |
| `PROCESSED` | `CANCELED` | BR-OR-CAN-001 | Fulfillment has not shipped; payment compensation initiated |
| `DELIVERED` | `REFUNDED` | BR-OR-REF-001 | Refund balance is sufficient and provider confirms refund |

Terminal states have no outgoing transitions. No operation may assign a status outside the declared set.

### `order_product_download` lifecycle

- **States:** `AVAILABLE` (initial), `EXPIRED` (terminal), `REVOKED` (terminal)
- **Transitions:**

| From | To | Trigger | Guard |
|---|---|---|---|
| `AVAILABLE` | `EXPIRED` | BR-OR-DIG-001 | Current time is after `expires_at` |
| `AVAILABLE` | `REVOKED` | BR-OR-DIG-001 | Order compensation or administrative revocation |

### `fulfillment_orders` lifecycle

- **States:** `REQUESTED` (initial), `IN_PROGRESS`, `SHIPPED`, `DELIVERED` (terminal), `CANCELED` (terminal)
- **Transitions:**

| From | To | Trigger | Guard |
|---|---|---|---|
| `REQUESTED` | `IN_PROGRESS` | BR-OR-FUL-001 | Fulfillment provider accepted request |
| `REQUESTED` | `CANCELED` | BR-OR-CAN-001 | Order cancellation completed before dispatch |
| `IN_PROGRESS` | `SHIPPED` | BR-OR-FUL-001 | Shipment reference exists |
| `IN_PROGRESS` | `CANCELED` | BR-OR-CAN-001 | Provider confirms cancellation |
| `SHIPPED` | `DELIVERED` | BR-OR-FUL-001 | Shipment update confirms delivery |

## Data Invariants

| Invariant ID | Statement | Entity | Kind | Tier |
|---|---|---|---|---|
| INV-OR-001 | An order status must be one of the declared lifecycle states. | `orders` | constraint | both |
| INV-OR-002 | Terminal order states cannot transition to another state. | `orders` | monotonic-status | both |
| INV-OR-003 | An order total and every persisted total component are immutable after acceptance, except separately identified refund/credit components. | `orders`, `order_totals` | constraint | app |
| INV-OR-004 | `refunded_amount` must not exceed captured amount. | `orders` | reconciliation | both |
| INV-OR-005 | A purchased line quantity must be positive. | `order_products` | constraint | db |
| INV-OR-006 | A download count cannot be negative. | `order_product_downloads` | constraint | db |
| INV-OR-007 | Each event ID and idempotency key is processed at most once per tenant/store. | `order_inbox` | referential/idempotency | both |
| INV-OR-008 | A fulfillment order belongs to exactly one order within a tenant/store. | `fulfillment_orders` | referential | db |
| INV-OR-009 | `order_total = SUM(order_totals.value WHERE is_refund = false)` at acceptance, with refund applications tracked separately. | `orders`, `order_totals` | computed | app |
| INV-OR-010 | An order history record cannot be updated or deleted through the service API. | `order_status_history` | append-only | app |
